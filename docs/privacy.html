Memoka プライバシーポリシー

1. 基本方針

Memokaはローカルファーストのノートアプリです。ノートの作成・編集・検索にMemoka専用アカウントは不要です。 ノート本文、タイトル、検索語、クリップボード、添付ファイル、WorkspaceのパスをMemokaのサーバーへ送信しません。 テレメトリー、広告、クラッシュレポートの自動送信を行いません。

Google Drive連携は任意です。利用者が接続を開始・認可するまでGoogleへ接続しません。 認可後は、利用者が有効にした保存先へのバックアップなど、以下に説明する目的で通信します。

2. 端末内のデータとローカル履歴

ノートと添付ファイルは、利用者が選んだWorkspaceに保存します。 Workspace内の.memoka-backups/resticにはノートと添付ファイルの自動履歴を保存します。 このローカル履歴にはパスワードを設定しません。Workspaceへアクセスできる人は過去世代も読めます。

削除済みノート、過去の本文、本文から参照されなくなった添付も履歴の保持対象です。 現在の表示から削除することと、過去データの消去は同じではありません。 履歴は保持設定に従って整理しますが、保存先の無効化やアプリの終了中などには整理が完了していない場合があります。

CLIと履歴プレビューはノート内の外部URLを取得せず、添付も選んだWorkspace・世代の保存済みデータだけを読みます。 同じWorkspaceを開いているプロセスへのCLI接続は、同じOSユーザーだけが利用できるローカル通信を使います。

3. 追加バックアップと暗号化

任意の追加保存先は、利用者が選んだローカルディレクトリ、または明示設定したGoogle Driveです。 バックアップはResticで暗号化します。ローカル履歴と同じく、過去の本文、ゴミ箱のノート、参照されなくなった添付も保存対象です。

追加保存先の暗号化用パスワードはOS資格情報ストアに保存し、必要なRestic子プロセスの環境へ渡します。 コマンド引数、通常ログ、設定ファイル、バックアップ内容には保存しません。 別環境での復旧に必要なパスワードは、利用者自身でも安全に保管してください。 パスワードを失うとバックアップ内容を復号できず、提供者がパスワードを再発行して復旧することもできません。

4. Google Driveでアクセスする情報と利用目的

Google Drive連携は現在実験的で、実アカウントでの認証更新・別PC復旧は未検証です。 公式AppImageとCLIにはMemoka用のDesktop OAuthクライアント設定を組み込みます。 これはアプリの識別用設定であり、利用者のGoogleトークンやバックアップパスワードではありません。

要求する権限はhttps://www.googleapis.com/auth/drive.fileだけです。 アプリが作成したファイルや利用者がアプリでの使用を許可したファイルへの権限であり、Drive全体へのアクセス権限ではありません。 ただし、「特定の1フォルダーだけのOAuth権限」ではありません。 GoogleアカウントのパスワードをMemokaに入力する必要はありません。

連携時には、次の情報を取り扱います。

  • 暗号化バックアップとファイル情報：専用フォルダーとその中のバックアップを作成・保存・一覧取得・読み出し・検証・復旧・保持整理するため、ファイル内容、ID、名前、サイズ、時刻、親フォルダー、削除状態、アプリ用属性などを扱います。フォルダーの名前や属性にはWorkspace ID・保存先IDなどの識別情報を含みます。

  • バックアップの親フォルダー：自動作成するMemoka、または利用者がブラウザのGoogle Pickerで選んだフォルダーのID・名前・書き込み権限・アクセス可能な祖先情報を、配置先の確認に使います。親ID・名前・自動選択かどうかをGoogle接続ごとに端末内へ記憶します。選んだ親の中へ新しい専用フォルダーを作り、親そのものや既存の無関係なファイルを削除・移動しません。

  • Googleアカウント識別子（permissionId）：再認証時に別アカウントへ誤って接続しないよう確認するために取得し、Workspace外の端末内の接続メタデータに保存します。接続名は利用者が設定したラベルを使います。

  • ストレージ容量情報（storageQuota）：同梱rcloneによる接続確認・トークン更新の過程で、容量上限や使用量を取得します。処理中のメモリで扱い、MemokaのWorkspaceや接続メタデータへ保存しません。

  • 認証トークン：利用者が許可したGoogle Drive操作を行い、認証を更新するために使用します。保存方法は次の項目に記載します。

転送は、利用者の端末から同梱rcloneを通じてGoogleへ直接行います。バックアップの内容はResticの暗号文ですが、 GoogleにはIPアドレス、APIリクエスト、転送量、時刻、ファイルサイズ、専用フォルダー表示名などが伝わります。 これらの情報まで暗号化で隠すものではありません。 Google側での情報の取り扱いにはGoogleのプライバシーポリシーが適用されます。

Memokaは、Google APIから取得する情報を、このポリシーで説明する連携機能のためにのみ使用します。 広告、情報の販売、信用評価、AIモデルの学習のために使用しません。提供者がバックアップ内容を受信・閲覧する仕組みはありません。 Google APIから取得した情報の利用と第三者への提供は、Limited Useの要件を含む Google API Services User Data Policyに従います。

5. Googleの資格情報の保存

Googleの認証トークンはWorkspace外の暗号化されたrclone設定へ、その復号鍵はOS資格情報ストアへ保存します。 Resticのバックアップパスワードとは別に管理します。トークンや鍵は通常ログ、Workspaceデータベース、バックアップ、 画面側の状態には含めず、Memoka独自のサーバーへ送る構成もありません。

資格情報ストアが利用不能なら処理を保留し、平文の設定ファイルへ保存する代替処理は行いません。 ただし、同じOSユーザーが子プロセスの環境を閲覧できることまで防ぐものではありません。 アカウント識別子、接続ラベル、接続先フォルダーIDなど、接続の確認に使うメタデータはトークンとは別に端末内で保持します。

6. 保持・接続解除・削除

追加保存先の世代は、利用者が設定した直近・日次・月次の保持条件に従って整理します。 転送や整理の停止・失敗中には過去のデータが残る場合があります。 保存先を無効化すると、その保存先への以後の自動転送を停止します。進行中の処理には中止操作も利用できます。

Memoka内の「接続を解除」は端末側の接続情報を削除・停止する操作です。Google側の認可取消は行いません。 保存先を残して接続を停止する場合、認証トークンの設定と復号鍵を削除し、再接続のためのアカウント識別子などのメタデータは残します。 当該接続を利用する保存先をすべて解除したうえで接続を解除すると、その接続の端末内メタデータも削除します。 同じ接続を使う保存先がほかにもある場合は、それらへの影響を確認してください。

Google側の認可を取り消す場合は、Googleアカウントの接続管理からMemokaのアクセス権を削除してください。 保存先の解除、認可の取消、アプリのアンインストールでは、Google Driveやローカルの保存済みバックアップは削除されません。 不要なバックアップは利用者自身で各保存先から削除してください。端末内のノートや履歴も、不要になったWorkspaceで別途管理してください。

保持整理で不要になったGoogle Drive上のデータはDriveのゴミ箱へ移します。Memokaがゴミ箱全体を空にすることはありません。 保持整理の完了とGoogleの容量回復は異なります。完全な削除が必要な場合は、Driveのゴミ箱に残った該当データも確認してください。 提供者は利用者のWorkspaceやDriveのバックアップを保管しないため、利用者に代わってそれらを削除することはできません。

7. 診断・一時キャッシュ・更新確認

診断ログはOS標準のMemokaログディレクトリへローカル保存し、最大5 MiBのファイルを合計3世代まで保持します。 ログは自動送信されません。問い合わせなどで共有する場合は、利用者自身が内容を確認してください。

転送の高速化のため、他ユーザーからのアクセスを制限した一時ディレクトリにResticの作業キャッシュを作ります。 転送ジョブ終了時に削除しますが、OSの異常終了や強制終了では残る場合があります。利用者の既存Resticキャッシュは使いません。 バックアップ画面の進捗情報は、工程・世代数・経過時間・通信量などの限定した情報をローカルで記録・表示します。 転送ツールの生ログ、ファイル名、トークン、パスワードを進捗情報として保存・表示しません。

公式AppImageは起動後に更新の有無を確認するため、GitHub ReleasesへHTTPSで接続します。 この通信ではGitHubへIPアドレスなどの通常のHTTP接続情報が伝わり得ます。 更新のダウンロードとインストールは、利用者が:updateで明示的に確定した場合だけ実行します。

8. 公開サイト

Memokaの公開サイトはGitHub Pagesで配信する静的ページです。Memoka独自のアクセス解析、広告、Cookieによる追跡、 外部フォントの読み込みは行いません。サイトの閲覧時には、配信元のGitHubにIPアドレスなどの接続情報が伝わります。 GitHub Pagesの説明によると、 GitHubはログインの有無にかかわらずセキュリティのために訪問者のIPアドレスを記録します。 配信元での情報の取り扱いはGitHubのプライバシーに関する声明を参照してください。

9. 変更とお問い合わせ

このポリシーを変更する場合は、公式プロジェクトと公開サイトに改訂版と更新日を掲載します。 Googleユーザーデータを当初の説明とは異なる目的・方法で利用する場合は、事前に変更を通知し、必要な同意を得ます。

一般的なお問い合わせはGitHub Issuesで受け付けます。 Issueは公開されるため、個人情報、ノート内容、認証情報、バックアップパスワードを投稿しないでください。 Google連携について個人情報を含むお問い合わせが必要な場合は、Googleの認可画面に表示されるサポートメールアドレスを利用してください。 脆弱性の報告方法はSecurity Policyを参照してください。
